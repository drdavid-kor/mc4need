# 实现与状态约束

## 数据与身份

Cloudflare Worker 服务 API，静态资源由同一 Worker 的 Assets 提供，D1 保存关系数据。每次平台访客创建 256 位随机 bearer token，只存 SHA-256 哈希；客户端凭证单独存在本机限制权限的 `identity.json`。不接受用户任意提交的麦当劳 accountId 作为身份。

CLI token 有效 90 天，网页会话 7 天；一次性链接 5 分钟，通过 URL fragment 传到网页，再 POST 兑换 HttpOnly、SameSite=Strict cookie。读取 fragment 后立即清除地址栏。过期/重放失败，跨源写操作拒绝。`auth revoke` 撤销该用户会话与待兑换链接。

私密配送姓名、电话、门牌及自愿联系方式使用 APP_SECRET 派生 AES-GCM 密钥，加密后保存。公开数据明确投影，不输出这些字段。已释放的赞助尝试不再能读取该需求的当前私密配送资料，避免发起方更新后泄露给旧赞助人。公开身份并非实名、机构资质或官方验真。

可选邮箱的验证/恢复链接 15 分钟有效，一次性消费。只有验证成功后关联邮箱并开启邮件通知，网页可关闭。未配置邮件服务时接口明确返回不可用，UI 不伪装邮件已发送；不影响其他流程。

## 整单赞助

`needs` 保存一期需求与版本，`attempts` 保存赞助尝试；`one_active_sponsor` 唯一部分索引保证同一期一个 active=1 的赞助。公开文字或菜单更新仅允许无活动赞助时，并返回草稿重新确认。

1. quoting：默认 5 分钟独占锁。可退出或过期释放。
2. creating：当前报价与明确确认后，数据库条件更新只能成功一次。AI 只有取得成功响应后才调用一次官方创建。
3. uncertain：官方响应未知、断连或矛盾。持续占用，必须对账。
4. pending：从官方创建时间计付款窗口，当前平台默认 10 分钟；若官方截止更早取较早值。该数值是当前实现配置，不代表已实测的官方有效期。
5. paid / preparing / delivering / delivered：仅客户端报告，保留时间与来源；delivered 不自动完成需求。
6. late：实际创建晚于接单截止，不正常接单、不鼓励付款，不放给下一人。
7. cancelled / expired：只有客户端明确报告未付款且没有此前付款证据时才可释放；过截止则关闭。已付或付款不明不自动开放替代订单。取消成功不自动设退款到账。

数据库 revision 防止并发覆盖，每次状态修改附独立 mutation ID，观察记录仅在对应修改成功时写入。订单号哈希唯一且不可替换，实际创建时间不可改，付款截止不可延后。幂等键拒绝重复写入；过旧状态拒绝，新到的矛盾状态留待核实。

仍有信任边界：恶意客户端能伪报状态和未付款；当前没有官方签名/回调佐证，因此不声称不可伪造。管理员没有强行创建第二单的解锁按钮。

## 收餐、取消与重复

收餐只允许发起方。收到与反馈是独立字段，可一次提交；只有 received + 非空且获准公开的反馈才完成。重复提交不更改完成事实；后续异常独立记录，保留历史反馈。

取消申请同时写入订单留言并生成对方站内通知，另保留实际取消结果与退款状态。具体麦当劳操作仍在赞助人账号里。站内消息、私密联系资料只对双方可见。

每五分钟维护任务仅处理平台数据：释放创建前过期锁、关闭已过接单截止且无有效订单的需求、清理过期凭证，并在上一期用餐时间过去后生成一个下一期草稿。下一期清空餐价/配送核实时间，需发起方再确认。周期任务绝不调用麦当劳 MCP。

## 内容与运行边界

每分钟/IP 基础写操作限频，body 上限 20 KB；每人最多 10 个未完成需求和 3 个未决赞助。此为基本滥用防护，不宣称防住分布式滥用。举报、内容隐藏/恢复、异常队列与审计日志供运营使用。

页面 CSP、no-referrer、nosniff、frame-ancestors 限制外部脚本和嵌入；真实定位使用 OpenStreetMap iframe，地图供应商会接收浏览请求。未嵌第三方分析或广告脚本。

所有时间存毫秒，金额存人民币分。官方订单/收货/身份数据不会被整个对象透传到平台。CLI 严格只向正式平台或显式本地测试地址发送平台凭证。
