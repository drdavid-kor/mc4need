更新：2026-10-16。依据本轮用户明确选择更新。本文件是产品交付范围，不是完成声明；当前实现和未验证项见 [验证记录](verification.md)。历史材料留在本地归档，不作为实施依据。

**Mc4Need — Sponsor a meal. Be part of it.**

## 当前体验

网页发现需求并复制专属 Prompt → 用户 AI 检查/安装 CLI + Skill → 建立可选邮箱绑定的访客会话 → 通过本人已连接的麦当劳 MCP 发布需求或承担整单 → 本人确认订单并完成官方支付 → 客户端同步状态 → 发起方确认收餐并反馈。

网页承担公开展示、地图定位、案例、登录后的记录/留言/反馈和通知；麦当劳操作由用户自己的 AI 客户端执行。此前“网页脱离 AI 独立点餐”的要求已由用户同意调整。麦当劳 Token 留在用户已有客户端连接中，平台不集中托管。

## 必交项

| 交付项 | 范围与验收重点 |
|---|---|
| GitHub Public repo | 用户个人账号下公开源码、可运行内容、安装部署说明、参赛文件与脱敏配置；无个人凭证或私密订单资料 |
| 在线平台 | HTTPS 入口；手机/桌面展示需求、指定餐食总份数、地点与地图、进展来源和时间、支持者及收餐反馈 |
| Copy-paste Prompt | 支持赞助与发起需求；携带可信安装信息及需求编号，运行时重取数据；不夹带凭证或跳过下单确认 |
| CLI + Skill | 安装、依赖准备、技能加载、平台会话、发布/赞助/查询/取消/沟通；有版本、校验、自检、升级及支持矩阵 |
| 开放发布与访客身份 | 无邀请、无强制邮箱验证也能完成发布/赞助；邮箱推荐用于恢复和通知 |
| 整单生命周期 | 发起方定餐食，一人承担整单；独占锁、实时算价、明确确认、待支付订单、官方支付及客户端状态同步 |
| 时间与重复需求 | 最晚接单时间；从订单创建成功计付款时限；每期发起方重新确认；不自动下单或扣款 |
| 沟通与异常 | 订单留言、私下自选联系方式、站内及可选邮件；取消申请、实际取消及退款分别记录 |
| 完成案例 | 发起方确认收到并反馈后才完成；演示与真实持续区分 |
| 三类示例 | 集体生日、急救培训、校园篮球；“演示案例 · 模拟完成”，不下真实单、不计真实成果 |
| Live 案例能力 | 接收线下引入与公开自助发布的真实需求，按实际进度展示；至少一例真实完成为联合验证目标，依赖真实参与者 |
| 管理与交接 | 后台管理示例、举报和异常；配置、账号归属、费用、备份恢复、回滚与维护责任 |
| 传播与参赛 | README、截图和演示、X / 小红书草稿、报名材料及实际执行结果；成功需官方回复，不承诺 Star 数或获奖 |

## 首版边界

不做拆份认领、多人拼单、赞助人自行替换餐食、先认领后延期付款、逐笔赞助审批、强制邮箱验证、邀请专属发布、集中麦当劳 Token 托管、自动点餐/扣款、原生 App、复杂推荐/信誉分，以及商业化和广告权益市场。

姓名/昵称/匿名与统一致谢保留。定期需求逐期确认，不是支付订阅。公开发布可配合基础防滥用与运营处置，但不能以管理员代录替代正常用户路径。

## 技术与外部依赖

1. 平台身份、一次性网页登录、恢复与权限控制待验证，不能信任任意上报 accountId。
2. 跨账号地址、菜单、时段和价格需重验，不复用不适用的账号数据。
3. 安装矩阵、创建时间、支付有效期、断连对账和锁释放需实测。
4. 客户端报告用于展示进展，无平台独立验真承诺；最终收餐来自发起方确认。
5. 实际场景与 MCP 服务条款适用边界仍需核实，本文件不声明已获得特殊授权。
